# Editing MDAT and SMST in Blender 5.2

Tomba2Edit uses Blender's built-in **Wavefront OBJ** importer and exporter.
No add-on, private Blender format or metadata sidecar is required. The existing
glTF buttons remain useful for rendering/animation exports; use the OBJ buttons
for geometry that will go back into the game.

1. Open your disc in Tomba2Edit. Select an MDAT resource, or open an SMST and
   select **one part** in its parts list.
2. Click **Export Blender OBJ**. Keep the OBJ, MTL and PNG files together.
3. In Blender 5.2, use **File → Import → Wavefront (.obj)**. Use scale **1**,
   Forward **-Z**, Up **Y**. One Blender unit represents 100 game units.
4. Edit the mesh. You may replace the geometry entirely, add/remove vertices
   and faces, or change UVs and vertex colours. Assign the exported `T2_...`
   materials to newly created faces. These materials identify the destination
   game's texture pages, palettes and draw settings; retain their names.
5. Use **File → Export → Wavefront (.obj)** with scale **1**, Forward **-Z**,
   Up **Y**, **UV Coordinates**, **Materials** and **Vertex Colors** enabled.
   Leave **Triangulated Mesh** disabled to retain quads. Export only the meshes
   you intend to replace; the export includes evaluated object transforms.
6. Back in the same Tomba2Edit resource/part, click **Import Blender OBJ**.
   Inspect the staged result, then use the existing export-files or disc-export
   workflow to save it to a separate output disc.

An MDAT import replaces its complete geometry and rebuilds its cell pointers.
An SMST import replaces only the selected part. Other part bodies, including
opaque headers and trailers, stay byte-identical; later part offsets change
when the selected body grows. Part numbers and the original collision resources
are retained. A new visual level therefore still has the original level's
walkable paths and invisible barriers.

## What is preserved and checked

* An unedited OBJ round trip recovers the original binary resource exactly,
  including unknown fields and padding. Matching tolerates Blender reordering
  vertices/faces and rotating a face's first corner, while preserving winding.
* Coordinates round to integer game units and must fit signed 16-bit storage.
  UVs map to the material's 256×256 PSX page. Vertex colours use the full 0–15
  game range, encoded as 0–1 in OBJ; neutral is 9/15. Enable Vertex Colors on
  export to retain edits to them. Missing colours preserve unchanged packets;
  new faces without colours use neutral shading.
* Faces must be triangles or quads. Triangulate n-gons yourself. New MDAT faces
  must fit its original grid, and faces spanning more than two cells must be
  subdivided. New geometry is assigned to cells by its horizontal centre.
* Unknown material names, missing UVs, non-finite/out-of-range coordinates,
  invalid indices and excessive data are rejected before staging anything.
* Growth defaults to zero for unknown allocations. US retail Town of Fishermen
  uses the known SDAT pool at `0x8018A000`; imports account for every staged
  edit and sector padding and stop before `0x801FD000`. This is an allocation
  check, not a guarantee that any arbitrarily dense scene will run at full speed.

The OBJ workflow edits geometry, UVs and colours using installed game textures.
Editing a PNG or assigning an arbitrary Blender material does not install new
texture data into the PSX image archive. External model ports must first arrange
their textures in destination VRAM. The example below does this separately.

## Requested Tomba 1 example

Local results are in `work/blender_geometry`:

* `Village_of_All_Beginnings_for_Tomba2.blend`: all **574 triangles and 3,147
  quads** from Tomba 1's first level, positioned in the Town of Fishermen grid.
* `WMD_52FF_Model001_for_Tomba2.blend`: the requested A006.GAM `+0x160C0`,
  WMD `0x52FF`, Model 001: **11 quads**, replacing SMST part **62** only.
* `Tomba2-Blender-Demo.cue` and its BIN: the rebuilt test disc. The CUE refers
  to the original audio track under `bincue`; keep that relative path intact.
* `TOMBA2.DAT`, `TOMBA2.IDX`, `TOMBA2.IMG`: the exported archive files.
* `validation.json`: byte hashes, counts and protected-resource comparisons.

Both example models passed through Blender 5.2's native OBJ import/export.
Their Tomba 1 textures were reduced to one quarter of their width and height
to fit unused VRAM. New uploads avoid original IMG claims and occupancy found
in the local Town of Fishermen PCSX savestate. Existing texture uploads remain
unchanged. These are visual replacements with the original Town collision,
placements, actors and scripts, rather than a port of Tomba 1's gameplay.

## Rechecking

Run `python -m unittest discover -s tests -p test_obj_exchange.py -v`.
The local retail Blender test uses files generated by
`work/blender_geometry/native_roundtrip.py`; synthetic tests run without a ROM.
The example preparation, Blender pass, disc rebuild and emulator harness are
also saved in that directory. They read the user's local game files; no ROM,
BIOS or emulator binary belongs in source control.

Blender's native OBJ settings are documented in the
[Blender manual](https://docs.blender.org/manual/en/latest/files/import_export/obj.html).
